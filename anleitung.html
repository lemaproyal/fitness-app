Fitness aufs Handy

Von deinem Rechner auf den Startbildschirm deines Android-Handys — ohne Play Store, ohne APK, ohne Android Studio. Einmal einrichten, danach genügt Hochladen.

16Dateien
110 KBGesamtgröße
~25 Minbeim ersten Mal
0 €Kosten

Was du brauchst

  • Den Ordner FITNESS auf deinem Rechner — hast du
  • Node — ist installiert
  • Eine E-Mail-Adresse für das GitHub-Konto
  • Ein Android-Handy mit Chrome

Teil 1 — Paket schnüren

Rechner
  1. 01

    PowerShell im Projektordner öffnen

    Ordner FITNESS im Explorer öffnen, mit gedrückter Umschalt-Taste in einen leeren Bereich rechtsklicken und PowerShell-Fenster hier öffnen wählen.

    Alternativ: In die Adressleiste des Explorers powershell tippen und Enter drücken.

  2. 02

    Paket bauen

    node werkzeuge/paket-bauen.js

    Das sammelt genau die Dateien, die zur App gehören, im neuen Ordner veroeffentlichen. Server, Startdatei und Werkzeuge bleiben draußen — die gehören zur Entwicklung, nicht auf den Webserver.

    Am Ende muss dort stehen:

    16 Dateien, 110 KB gesamt
Service-Worker-Version: v1
  3. 03

    Versteckte Dateien sichtbar machen

    Im Explorer oben auf Ansicht → Einblenden → Ausgeblendete Elemente.

    Im Paket liegt die Datei .nojekyll. Windows versteckt Dateien, die mit einem Punkt beginnen — ohne diesen Schritt würdest du sie beim Hochladen übersehen.

Teil 2 — GitHub-Konto anlegen

Rechner
  1. 04

    Auf github.com registrieren

    github.com/signup öffnen und E-Mail-Adresse, Passwort und Benutzernamen eingeben.

    Der Benutzername steht später in der Adresse deiner App. Aus hape wird https://hape.github.io/fitness/. Wähle also etwas, das dir auf Dauer recht ist.
  2. 05

    E-Mail bestätigen

    GitHub schickt dir einen Code. Ohne die Bestätigung lässt sich später keine Seite veröffentlichen.

Teil 3 — Ablage für die App anlegen

Rechner
  1. 06

    Neues Repository erstellen

    Oben rechts auf das + klicken → New repository.

    Ein Repository ist einfach ein Projektordner bei GitHub.

  2. 07

    Einstellungen setzen

    • Repository name: fitness
    • Description: leer lassen
    • Public auswählen — nicht Private
    • Add a README file nicht ankreuzen
    Warum öffentlich? Im kostenlosen Tarif funktioniert GitHub Pages nur mit öffentlichen Repositories. Hochgeladen wird ausschließlich Programmcode — deine Übungen, Notizen und Trainingsdaten liegen in der Datenbank deines Handys und verlassen es nie.
    README wirklich weglassen. Nur ein komplett leeres Repository zeigt im nächsten Schritt den Link zum Hochladen an.
  3. 08

    Anlegen

    Unten auf Create repository.

Teil 4 — Dateien hochladen

Rechner
  1. 09

    Hochladen starten

    Auf der Seite des leeren Repositories steht ein Satz mit dem Link uploading an existing file. Darauf klicken.

    Findest du ihn nicht, geht es auch über Add file → Upload files.

  2. 10

    Inhalt des Paketordners hineinziehen

    Ordner FITNESS\veroeffentlichen im Explorer öffnen, mit Strg+A alles markieren und in das Browserfenster ziehen.

    Den Inhalt ziehen, nicht den Ordner. Ziehst du den Ordner veroeffentlichen selbst hinein, landet alles eine Ebene zu tief und die App wird nicht gefunden.
  3. 11

    Vollständigkeit prüfen

    GitHub listet die hochgeladenen Dateien auf. Es müssen erscheinen:

    index.html          src/db.js          icons/icon-192.png
verwaltung.html     src/pwa.js         icons/icon-512.png
manifest.webmanifest  src/schnitt.js   icons/icon-maskierbar-512.png
sw.js               src/start.js
.nojekyll           src/stammdaten.js
                    src/verwaltung.js
                    src/video.js
                    src/youtube.js

    Das sind 16 Einträge. Fehlt .nojekyll, hast du Schritt 03 übersprungen — nicht schlimm, siehe Schritt 13.

  4. 12

    Speichern — der wichtigste Klick

    Bis ganz nach unten scrollen. Unter der Dateiliste kommt ein Abschnitt Commit changes mit zwei Textfeldern, darunter der grüne Knopf Commit changes.

    Die Textfelder kannst du leer lassen.

    Ohne diesen Klick ist nichts gespeichert. Die Dateiliste zeigt nur, was hochgeladen werden soll. Verlässt du die Seite vorher, bleibt das Repository leer — und in Teil 5 steht dann „You must first add content to your repository", ohne dass main zur Auswahl steht.

    Prüfen: Danach landest du auf dem Reiter Code. Dort müssen index.html, sw.js sowie die Ordner src und icons aufgelistet sein. Erst dann weiter.

  5. 13

    Nur falls .nojekyll fehlt

    Add file → Create new file, als Dateinamen .nojekyll eintragen, Inhalt leer lassen, unten Commit changes.

Teil 5 — Seite freischalten

Rechner
  1. 14

    Einstellungen öffnen

    In der Leiste über dem Repository auf Settings — ganz rechts, mit Zahnrad.

  2. 15

    Pages auswählen

    In der linken Spalte nach unten scrollen bis Pages.

  3. 16

    Quelle festlegen

    • Unter Source: Deploy from a branch
    • Unter Branch: main
    • Daneben der Ordner: / (root)
    • Dann Save
  4. 17

    Auf die Adresse warten

    Ein bis zwei Minuten warten, dann die Seite neu laden. Oben erscheint ein Kasten mit deiner Adresse:

    https://DEINNAME.github.io/fitness/

    Beim allerersten Mal kann es bis zu fünf Minuten dauern. Unter Actions siehst du, ob noch gearbeitet wird — ein gelber Punkt heißt „läuft noch", ein grüner Haken „fertig".

    Adresse aufschreiben. Du brauchst sie gleich am Handy. Am einfachsten schickst du sie dir selbst per E-Mail.

Teil 6 — Am Rechner gegenprüfen

Rechner
  1. 18

    Adresse öffnen

    Die Startseite muss erscheinen: Titel Fitness, darunter vier Kacheln mit Zahlen und die Schaltfläche Übungen verwalten.

  2. 19

    Der entscheidende Test

    Auf der Startseite darf kein Hinweis Offline-Betrieb nicht aktiv stehen.

    Ist der Hinweis weg, funktioniert der Offline-Betrieb. Genau das ist der Unterschied zwischen einem Lesezeichen und einer echten App.

    Steht er noch da: einmal neu laden. Bleibt er, siehe Störungstabelle unten.

  3. 20

    Offline gegenprüfen

    Seite einmal neu laden, dann WLAN am Rechner ausschalten und erneut neu laden. Die Seite muss weiterhin erscheinen.

    Danach WLAN wieder einschalten.

Teil 7 — Auf dem Handy installieren

Handy
  1. 21

    Adresse in Chrome öffnen

    Die Adresse aus Schritt 17 in Chrome aufrufen.

    Chrome, nicht Samsung Internet oder Firefox. Das Ablegen auf dem Startbildschirm klappt dort nicht gleich zuverlässig.
  2. 22

    Zum Startbildschirm hinzufügen

    Entweder erscheint unten von selbst der Hinweis mit dem Knopf Installieren — oder du gehst über das Menü: die drei Punkte oben rechts → Zum Startbildschirm hinzufügen beziehungsweise App installieren.

    Namen bestätigen, fertig.

  3. 23

    App vom Startbildschirm starten

    Das rote Hantelsymbol antippen. Die App muss im Vollbild ohne Adressleiste starten.

    Erscheint doch die Adressleiste, wurde nur ein Lesezeichen angelegt. Dann Symbol löschen und Schritt 22 über das Menü wiederholen.

  4. 24

    Einmal mit Internet durchklicken

    Startseite öffnen, dann Übungen verwalten antippen und wieder zurück.

    Damit lädt das Handy alle Dateien in seinen Speicher. Erst danach ist die App wirklich offline nutzbar.

  5. 25

    Flugmodus-Probe

    Flugmodus einschalten, App vom Startbildschirm öffnen. Sie muss normal starten und sich bedienen lassen.

    YouTube-Videos brauchen weiterhin Internet. Übungen, Texte, Notizen und Protokoll funktionieren offline — die Videos bleiben schwarz, bis du wieder Empfang hast. Das ist der Preis für Links statt eigener Aufnahmen.

Teil 8 — Übungen aufs Handy bringen

Rechner Handy
  1. 26

    Am Rechner exportieren

    App öffnen → Übungen verwalten → ⋯ → Exportieren.

    Es lädt eine Datei wie fitness-sicherung-2026-08-15.json herunter.

    Warum überhaupt? Die Datenbank liegt pro Gerät getrennt. Was du am Rechner angelegt hast, kennt das Handy nicht.
  2. 27

    Datei aufs Handy bringen

    Per E-Mail an dich selbst, über Google Drive oder per USB-Kabel in den Download-Ordner.

  3. 28

    Am Handy importieren

    App öffnen → Übungen verwalten → ⋯ → Importieren → die JSON-Datei auswählen.

    Danach zeigt die Startseite dieselben Zahlen wie am Rechner.

  4. 29

    Dauerhaft speichern erlauben

    ⋯ → Dauerhaft speichern anfordern antippen.

    Ohne diese Erlaubnis darf Android die Datenbank löschen, wenn der Speicher knapp wird. Vom Startbildschirm aus wird sie fast immer erteilt.

Teil 9 — Später aktualisieren

Rechner
  1. 30

    Versionsnummer hochzählen

    In sw.js steht ganz oben:

    const VERSION = "v1";   → auf "v2" ändern
    Das ist der Schritt, den man vergisst. Ohne neue Nummer behält dein Handy hartnäckig den alten Stand — es bevorzugt seine gespeicherte Fassung. Du lädst hoch, wunderst dich, und nichts ändert sich.
  2. 31

    Paket neu bauen

    node werkzeuge/paket-bauen.js

    Die ausgegebene Service-Worker-Version muss jetzt v2 lauten.

  3. 32

    Erneut hochladen

    Im Repository Add file → Upload files, wieder den Inhalt von veroeffentlichen hineinziehen, dann Commit changes.

    Gleichnamige Dateien werden ersetzt, nichts wird doppelt.

  4. 33

    Am Handy übernehmen

    App öffnen. Es erscheint Neue Fassung verfügbar mit einem Knopf Jetzt aktualisieren. Antippen — die App lädt sich selbst neu.
